## Objective

When an agent connects to a Rhino model, it can find the current document and its source material, produce and inspect the required drawings, and hand over design reasoning and usable files to the next Step. Completing a Step gives the agent an informed choice before removing the current document's temporary layers and objects.

Use [A1](https://app.notion.com/p/419e0a3941208167b381db15cfd7d41e), [A2](https://app.notion.com/p/419e0a39412081d18036db4f430fc992), [A3](https://app.notion.com/p/419e0a39412081479f49ef989a1980dd), their eight Sub-Actions, and the Slack decisions above. ## Work 3 · Handoff and Step completion

- Add optional Takeaways and Design rationale fields. Keep them distinct from the actual files in input_refs and output_refs. Preserve existing records and Loop/revision snapshots. Verify that a later connection can discover and read prior files.
- Deliver the existing `src/mcp/BASIC-INSTRUCTIONS.md` and adjacent `design_judgment.md` to the connected agent through the existing MCP guidance path. Create `design_judgment.md` as an empty file if it is absent. Keep document delivery in the guidance feature using the existing server, Bridge and runtime interfaces. Verify complete delivery, missing versus empty behavior, length, duplication and version changes across the supported connection paths. Dot custom instructions remain outside this scope.
- When an agent requests a transition to completed, return the warning and let the agent explicitly choose Yes or No in a follow-up tool call before changing the Step status or deleting model content. Use the following confirmation text or an equivalent with the full warning intact.

  > 다음 스텝에서도 사용해야 할 자료는 먼저 temp가 아닌 다른 레이어로 옮겨야 합니다. 현재 스텝을 완료하면 temp 및 그 하위 레이어에 속한 객체 전체가 삭제됩니다. 모든 하위 레이어도 삭제되며 최상위 temp 레이어는 유지됩니다. 로컬 블록 정의에서도 해당 레이어의 구성원이 삭제되어 temp 밖에 있는 인스턴스의 형상이 달라질 수 있습니다. 스텝 상태를 완료로 변경하시겠습니까?

- No cancels the transition and performs no cleanup. If materials must be retained, the agent first cancels, moves them outside temp, and starts a fresh completion attempt. Yes first commits the completed Step status to SQLite, then removes objects from the current document's temp tree and deletes all its descendants. The root temp layer remains. Layer membership defines temporary content. Scope deletion to the current document's own layers and objects. Preserve model resources outside the target tree, including drawings and their Update data. Cascade deletion of drawings generated from a clipping plane and new ownership metadata remain outside scope.
- Check confirmation and rejection, nested layers, empty descendants, deletion and status failure, and an already completed Step versus a subsequent transition back to completed. Report failures accurately and verify the resulting Rhino and SQLite states.
- A temp block instance is removed like any other temp object. Remove individual temp-layer members from local block definitions while retaining the definitions and their other members. If Rhino cleanup fails after SQLite has committed, report the retained completed status and the observed cleanup outcome. A repeated completed request performs no cleanup.
