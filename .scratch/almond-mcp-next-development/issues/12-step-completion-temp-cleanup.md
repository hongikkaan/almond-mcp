# 12: Step 완료 전 에이전트 선택과 temp 정리

**What to build:** 에이전트는 Step을 완료하기 전에 정리 범위를 확인하고 취소할 수 있다. 보존할 자료가 있으면 취소 후 옮기고 완료를 다시 요청할 수 있다.

**Blocked by:** None (can start immediately)

**Status:** integrated

- [ ] 실제로 completed로 바꾸려는 요청에만 경고와 Yes/No 선택을 반환한다. 경고는 상태 변경 또는 삭제 전에 표시되며 Rhino 팝업이나 열린 Rhino 명령·DB 잠금을 요구하지 않는다.
- [ ] No는 아무것도 변경하거나 삭제하지 않고 요청을 닫는다. 에이전트가 자료를 temp 밖으로 옮긴 뒤 새로 요청하고 그 새 요청에서 Yes를 선택하는 경우만 완료한다. 취소된 요청의 응답을 다른 요청에 재사용하지 않는다.
- [ ] Yes면 SQLite에 Step의 완료 상태를 먼저 저장한 뒤 현재 문서의 temp 트리에 속한 객체와 모든 하위 레이어를 삭제한다. 최상위 temp 레이어, temp 밖의 자료, 첨부 파일을 보존한다.
- [ ] 일반 상태 변경, 이미 완료된 Step, 이후 정상적인 재완료, 취소, 삭제 또는 DB 반영 실패를 비교한다. 실패를 성공으로 표시하지 않고 모델과 Step 상태를 확인한다.

**검증 상태**

`0df34f3`에 구현을, `16a0c51`에 공유 라우팅과 공개 계약을 통합했다. Step·Phase·DB·모의 Rhino 검사 84개와 Rhino SDK 컴파일이 통과했다. 실제 Rhino에서 No 후 재요청과 Yes를 확인했다. 하위 레이어 4개와 객체 9개를 제거했고, 최상위 `temp`와 중첩 블록의 남은 구성원·배치·메타데이터를 보존했다. 저장한 `.3dm`에서 빈 블록 정의와 외부 배치가 유지됨을 확인했다.
