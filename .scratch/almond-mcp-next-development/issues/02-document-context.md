# 02: 네임드뷰·Layout·레이어 트리 조회

**What to build:** 사용자가 프로젝트 초기 정보와 문서 조회에서 같은 기준으로 도면 뷰와 레이어 구조를 발견할 수 있다.

**Blocked by:** None (can start immediately)

**Status:** integrated

- [ ] 두 조회가 네임드뷰·Layout·합의된 메타데이터 수집을 공유하고, 이름과 식별 기준이 일치한다.
- [ ] 레이어 이름과 부모 관계 전부를 읽을 수 있는 들여쓰기 트리로 전달한다. 빈 목록, 깊은 계층, 서로 다른 부모 아래의 동명 레이어를 확인한다.
- [ ] 기존에 선택 가능한 관찰 섹션과 식별자는 유지하며, 긴 목록의 일부만 반환한 경우 그 상태가 드러난다.
- [ ] 활성 문서 정보와 Worksession 목록의 조회·응답 구성은 연결 뒤 사용하는 MCP 조회 도구에 둔다. 서버·Bridge·runtime 시작에는 문서 관찰 요청이 없다. 연결을 식별하고 보호하는 최소 문서 정보는 유지한다.

**검증 상태**

`256877f`에 통합. 오프라인 관찰 관련 검사 59개와 실제 stdio 초기화·모의 문서 관찰 검사, Rhino SDK 참조 컴파일 통과. 실제 Rhino 문서·첨부 검수 대기.
