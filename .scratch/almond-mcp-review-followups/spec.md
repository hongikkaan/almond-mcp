# Almond MCP 검토 후속 명세

익환과 합의한 세 가지 사용자 동작을 대상으로 한다. 수용 사례는 구현 후 검증할 기준이다.

## 사용자가 확정한 세 가지 동작

| 안건 | 사용자가 겪는 문제 | 바뀌어야 할 결과 |
|---|---|---|
| Plan 완료 | Plan을 마친 시점에 어떤 임시 자료를 정리할지 안내가 없다. | 사용자가 완료를 확인하고 Plan이 실제로 `completed`로 바뀐 호출에서만 정리 안내를 받는다. |
| 간섭 검사 | 계산을 끝내지 못한 결과를 보고도 간섭이 0건이라고 읽을 수 있다. | 검사 범위의 ‘간섭 없음’과 ‘미판정’을 구별하고, 미판정이면 확인된 대상과 공차를 알 수 있다. |
| 명시적 블록 캡처 | 한 타일에서 지원하지 않는 블록을 지정해도 다른 타일이 성공하면 이미지가 반환될 수 있다. | 명시한 최상위 블록 인스턴스가 있으면 호출 전체가 실패하고, 어느 입력에서 어떤 객체를 고쳐야 하는지 알 수 있다. |

## 수용 사례

**1. Plan 완료** — Plan은 목표와 Step을 가진 작업 단위이며, 사용자가 완료를 판단한다. `plan_12-update` tool의 기존 응답 안내(`next_step_guide`)에 다음 문구를 표시한다.

> 이 Plan 과정에서만 사용했고 이제 필요 없는 객체·레이어·레이아웃·Named View를 정리하세요.

- 최초 완료와 다시 열어 작업한 뒤의 재완료에서 각각 한 번 표시한다.
- 마지막 Step을 마친 경우, 이미 완료된 Plan에 완료를 다시 요청하거나 제목만 고친 경우, 완료 저장에 실패한 경우에는 정리 문구가 없어야 한다. 기존 오류와 부분 성공 처리는 그대로 적용한다.

**2. 간섭 검사** — 검사 결과를 보고 사용자가 추가 확인할 대상을 고를 수 있어야 한다.

- 요청 범위의 검사를 끝냈고 양의 부피가 겹친 쌍이 0개이면 ‘간섭 없음’으로 읽혀야 한다. 겹친 쌍이 있으면 확인된 건수를 반환한다.
- 객체를 검사할 수 없거나 쌍의 계산이 끝나지 않으면 ‘미판정’으로 표시한다. 확인된 객체나 쌍, 실패 이유, 확인된 공차와 단위를 함께 표시한다. 특정 대상이나 적용 공차를 알 수 없으면 해당 항목에 ‘확인 불가’를 표시한다.
- 앞 페이지에서 겹침을 찾았더라도 뒷페이지가 실패했다면 전체 건수는 미확정이다. 검사에서 의도적으로 제외한 대상은 지정된 범위 밖으로 처리한다.

**3. 캡처 입력** — `capture_02-inspection` tool에서 블록을 명시한 사용자가 오류 응답만으로 입력을 고칠 수 있어야 한다.

- 공통 `object_ids`에 일반 객체와 최상위 블록을 함께 넣거나, 여러 타일 중 하나의 `views[i].object_ids`에만 블록을 넣어도 호출 전체가 오류다. 문제 블록의 GUID와 공통 입력 또는 해당 타일 위치를 표시한다. PNG나 저장 경로는 반환하지 않는다.
- 명시적 객체 필터 없이 현재 화면에 블록이 보이는 경우는 허용한다. 블록과 무관한 개별 타일 오류에서는 성공한 타일의 이미지, 실패 타일 정보, `complete=false`를 보존한다.

## 기술 권장안과 검증 경계

| 안건 | 권장 적용 위치 | 오프라인에서 확인할 결과 |
|---|---|---|
| Plan 완료 | 기존 Plan 저장 단계에서 실제 상태 전환을 판별하고 저장 성공 후 응답에 안내를 덧붙인다. | 테스트용 Plan으로 완료·재완료·무변경·실패를 구분한다. 동시 완료 요청도 전환을 저장한 호출에만 문구가 나오는지 공개 응답으로 확인한다. |
| 간섭 검사 | `intersect_01-find` tool의 집계 응답과 `intersect_02-resolve` tool의 미판정 응답에 기존 검사 근거를 전달한다. 기하 계산 알고리즘은 유지한다. | 기존 검사 응답 예제로 0건·양수·미판정·페이지 실패를 대조한다. 확보한 공차와 단위가 보존되고, 받지 못한 값은 추정하지 않는지 확인한다. |
| 캡처 입력 | 기존 캡처 호출 안에서 이미 판별하는 블록 GUID와 입력 위치를 상위 오류로 전달한다. 별도 객체 조회나 새 Bridge는 추가하지 않는다. | 공통·타일별 블록 오류와 정상 부분 성공을 공개 응답의 오류 표시 및 이미지 유무로 구분한다. 기존 Bridge 소스 수정이 필요하면 해당 RHP를 빌드하고 산출물을 별도로 검증한다. |

세 동작을 각각 선행 조건이 없는 세 티켓으로 나누는 안은 사용자 확인을 기다린다. 확인 후 별도 단계에서 티켓을 작성한다. 구현 후 오프라인 검증을 먼저 하고, 이후 오케스트레이션 통합 테스트용으로 기존 Almond 루트에 반영할 예정이다. 이 명세의 수용 시험과 실제 Rhino 통합 검수는 미실행 상태다.

## 이번 범위 밖

- **Plan 후속 작업** — 도구는 정리 문구만 전달한다. 자동 삭제·삭제 실패 복구·부분 실패 정책, PDF 자동 생성이나 내보내기 기능 수정은 포함하지 않는다.
- **Loop** — Loop는 같은 Plan을 수행하는 회차다. 피드백 출처와 Goal 판단은 코드를 바꾸지 않고 사용 경과를 관찰한다.
- **PlanSection 120초** — 설치된 Codex에서 기존 PlanSection 한 도구만 대기 시간을 바꾸는 간단한 설정이 없어 보류한다. 공통 호출 대기는 변경 대상에서 제외한다.
- **Display Mode** — `list-01`~`list-04`의 View Display Mode Menu와 `Shade` 명령을 실제 UI에서 대조한 뒤 필터를 논의한다.
- 블록 캡처 지원 추가, 전체 도구의 오류 응답 개편, 요청 ID 복구, DB 재연결 개선, PDF 전용 출력과 종횡비 자동 검사는 별도 범위다.
