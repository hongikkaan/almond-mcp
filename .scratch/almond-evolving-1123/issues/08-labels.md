# 15 · 가시 픽셀 근거가 있는 객체 라벨

현재 labels는 Bounds.IsVisible 이후 상자 중심에 이름·GUID를 표시한다. 그룹 GUID가 멤버를 대체할 수 있다. 해당 방식은 완전 가림을 판별하지 못한다.

**선행 티켓** 없음

## 구현 경계

기존 labels 및 기본 false를 유지한다. 공개 SDK에서 입력 캡처와 같은 가시 픽셀의 소유 객체를 판별하는 경로가 확인될 때까지 새 옵션 구현은 보류한다.

## 수용 기준과 오프라인 검증

통합 시험 모델에는 완전히 가려진 벽, 가장자리만 보이는 두 번째 벽, 클리핑 면을 가로지르는 기둥, 배치 블록을 둔다. 라벨은 실제 노출 픽셀을 가져야 하며 배치 GUID·이름·레이어·재질·요청 키를 표시해야 한다. 모델 주석·선택은 보존한다. 기존 오프라인 fixture는 픽셀의 소유권을 검증하지 않는다.

## 재현할 시험 장면

별도의 빈 시험 문서에서 정면 평행 투영을 사용한다. 아래 범위는 카메라 기준 가로·세로 좌표이고 깊이는 앞에서 뒤로 증가한다. 불투명 음영 모드에서 앞벽과 뒤벽은 같은 색으로 둔다.

| 대상 | 배치 조건 | 새 객체 라벨의 수용 기준 |
|---|---|---|
| 앞벽 | 가로·세로 0~10, 깊이 1 | 앞벽의 가시 픽셀과 연결된 라벨 하나 |
| 완전 가림 벽 | 가로·세로 2~8, 깊이 2 | 라벨 없음 |
| 일부 노출 벽 | 가로 9~12, 세로 3~7, 깊이 3 | 가로 10~12의 노출부를 식별. 가려진 중심에만 라벨을 붙이면 실패 |
| 절단 부재 | 앞벽 밖에 기둥 두 개를 놓고 하나는 완전히, 다른 하나는 절반만 클리핑 | 완전히 잘린 기둥은 제외하고 남은 기둥의 노출부를 식별 |
| 블록 | 화면 빈 곳에 동일 정의의 인스턴스 두 개를 이격 배치 | 각 배치의 GUID를 구분. 정의 GUID를 두 번 표시하면 실패 |

라벨을 끄고 켜기 전후의 객체 수·GUID·선택 상태를 대조한다. 숨김 레이어, 선택 강조, 다른 표시 모드에서 같은 가시성 판단을 보장할지는 해당 모드별 시험에서 기록한다.

설치 SDK의 `RhinoViewport.IsVisible(BoundingBox)`는 시야와의 교차만 판정한다. `ZBufferCapture`에는 깊이와 월드 좌표가 있고 객체 ID는 없다. 같은 색의 겹침이나 그림자에서는 객체 하나를 제외한 이미지와의 RGB 차이도 가시성 판정 근거가 될 수 없다. 검증된 객체 식별 경로와 실제 시험 결과는 아직 없다.
