# rhino-almond 개발 지침

이 폴더는 Almond MCP를 활용한 Rhino 작업 스킬의 개발 원본이다. 실제 작업 세션의 문제와 사용자 지시를 근거로 스킬을 개선한다. 아래 세션 분석·커밋·배포 절차는 스킬 개선 작업에 적용하며, 단순 질의나 지정 문서만 수정하는 요청의 범위를 임의로 확대하지 않는다.

## 시작과 역할 분담

- `skill-creator` 스킬은 사용하지 않는다.
- 현재 스킬 관련 이전 memory를 참고하되, 현재 파일·도구·세션 기록과 대조한다. 개발 폴더와 실제 사용되는 전역 `rhino-almond` 스킬 경로를 확인한다.
- 시작 시 Git 상태와 기존 staged/unstaged 변경을 확인하여 이번 작업의 변경과 구분한다. 기존 사용자 작업을 덮어쓰거나 임의로 커밋하지 않는다.
- 세션 조회는 모델 `gpt-6-luna`, reasoning effort `xhigh`의 subagent에게 논리 세션 하나씩 맡긴다. 재개·fork·연결된 하위 검토는 같은 담당자가 분석한다. 가능한 동시 실행 자리를 채우고 완료되면 다음 세션의 새 agent를 배정한다. 주 agent는 최종 보고의 범위·근거를 확인해 종합·편집·검증한다.

## 세션 분석과 개선

- 사용자가 지정한 기간, 없으면 현지 어제~오늘을 대상으로 하되 **실제 배포된 기존 스킬의 마지막 본문 수정 이후 그 버전을 적용한 Rhino 작업만** 분석한다. 수정 시각·버전과 세션의 본문 로드 근거를 대조하며, 이름 언급만으로 적용을 인정하지 않는다. 분석 중 원복·편집으로 바뀐 작업 폴더 시각을 기준으로 삼지 않는다.
- 보관 JSONL 전체에서 후보와 제외 근거를 확인하고 대상 세션을 빠짐없이 분석한다. 각 세션의 공개 요청·호출·결과·후속 수정·완료 흐름을 끝까지 검토하고 필요한 소스·이미지를 조회한다. 색인·오류 집계를 내용 검토로 대신하지 않으며, 사실·추정·미확인 범위를 구분한다. 모든 세션 분석과 문제점 고찰을 마친 뒤 개선안을 구상하고 수정한다.
- `steered.md`는 `지시 내용 | 이번 처리 | 적용 문서 | 횟수` 표 하나만 덮어쓴다. 유사 지시는 한 행으로 합쳐 세션 구분 없이 횟수를 합산하며 원문·별도 읽기 설명은 넣지 않는다. 사용자 지시·전달문·에이전트 해석을 구분하고 복제·자기보고를 제외한다. 기간·출처·집계 근거는 별도 분석 기록에 둔다.
- 지시를 재사용 가능한 규칙으로 만들 수 있는지 검토한다. 프로젝트 고유 조건이나 일회성 지시를 보편 규칙으로 강제하지 않는다. 기존 지침과 통합하고 중복·충돌을 정리하여 규칙이 불필요하게 늘어나지 않게 한다.
- `추가할 사항.md`는 반영할 요구사항, `고민.md`는 검토할 문제의식으로 읽는다. 세션 근거와 대조해 스킬 개선에 반영하고, 원문 의도를 보존하면서 반영 위치·판단·남은 쟁점을 해당 문서에 기록한다.
- 사용자 지시 자체의 모호함이나 상충이 결과에 영향을 주었다면 근거와 함께 피드백하고, 더 명확한 지시 방법을 제안한다. 사용자 탓으로 원인을 단정하지 않는다.

## 검증·커밋·전역 반영

- 변경한 지침의 연결·중복·충돌을 확인한다. 코드 변경은 관련 호출부를 확인하고 변경 위험에 맞는 최소한의 유효한 검증을 수행한다. 실행이나 이미지 열람 없이 실제 Rhino 결과까지 검증했다고 주장하지 않는다.
- 이번 작업의 변경만 stage하고 staged diff를 검토한다. `추가할 사항.md`와 `고민.md`의 이번 작업 반영 기록도 커밋에 포함한다. 기존 변경과 같은 파일을 수정했다면 이번 작업 부분만 분리하며, 안전하게 분리할 수 없으면 임의로 포함하지 않고 사용자에게 확인한다.
- `git diff --cached --check`와 staged 파일·내용 확인 후 이번 작업분만 커밋한다. 커밋 제목은 `[Almond-Skill]`로 시작하고, 단순 diff 나열보다 이번 작업이 필요했던 이유와 개선 방식을 적는다. 다음 형식을 사용한다.

  ```text
  [Almond-Skill] 한 줄 요약
  작업 핵심 내용 :
  - 개선한 문제와 해결 방식
  현재 세션 :
  - 작업 맥락과 검증 결과
  ```

- 커밋 후 실제 사용되는 전역 스킬의 `rhino-almond` 폴더를 갱신한다. `SKILL.md`와 실행에 필요한 참조·스크립트·자산을 배포 대상으로 삼고, 개발용 `AGENTS.md`, 세션 분석 기록, `steered.md`, 고민·추가사항 문서, Git 메타데이터 등은 제외한다.
- 교체 전에 원본과 대상의 절대 경로·링크 여부·배포 파일 목록을 확인하고, 대상이 정확히 전역 `rhino-almond` 폴더인지 검증한다. 기존 전역 스킬을 복구 가능한 위치에 백업한 뒤 대상 내 기존 내용을 삭제하고 배포 자료를 복사한다. 다른 스킬이나 개발 원본은 삭제하지 않는다. 복사 후 파일 내용과 누락·잔여 파일을 확인하고 실패하면 복구한다.

## 최종 보고

- 발견한 문제, 반영한 개선, 검증 결과와 한계, 커밋 및 전역 반영 결과를 간결하게 보고한다.
- 스킬 개선 효과를 확인할 만한 다음 실험 과업이 있으면 짧게 제안한다. 수행하지 않은 검증과 사용자가 알아야 할 실제 위험을 명시한다.
