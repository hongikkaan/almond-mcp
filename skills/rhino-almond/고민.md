## 검토와 반영 — 2026-10-22

- 방문자센터에는 실제 이미지 열람과 후속 vision 검수가 있었다. 다만 초반 캡처는 지붕이 내부를 가렸고, 벽 모서리·이전 가구 잔재·샤워 시선 노출·계단참 틈을 늦게 발견했다. 따라서 원인을 단순히 “vision 미사용”으로 단정할 수 없다. [세션 분석](reviews/2026-10-22/visitor/audit.md)
- 시각자료의 개수와 solid/등록 성공이 공간 품질을 보장하지 않았다. `references/visual-review.md`에 보이는 근거·실제 판독·수정 후 재검수를, `references/workflow.md`에 이동·체류·프라이버시와 문·바닥·지지·배수의 연결, 반복 상세의 대표 구간과 경계 검토를 통합했다.
- Bonsai 예시의 평면 조직과 가구·문·동선의 관계는 품질 비교 대상으로 읽었다. 그 배치나 구조를 보편 규칙으로 복제하지 않고, 평단면의 사용 조건을 먼저 확인한 뒤 Almond 시공상세를 연결하도록 했다. 스킬 문구만으로 동등한 결과를 보장할 수는 없다.
- 남은 확인: 새 스킬로 문·계단·벽·바닥·참조 접점이 있는 작은 구간을 실제 구축하고 필수 뷰 전체를 검수해 결함 발견과 수정 여부를 평가한다. 이번에는 세션·코드·대표 이미지와 문서 연결을 검토했으며 새 Rhino 모델링을 실행하지 않았다.

## MCP 계약 정합 검토 — 2026-10-23

- 현행 MCP의 실제 문서·화면 조회와 C# `result/result_error` 계약을 대조해 기존 안내와 충돌하는 부분만 조정했다. 결과 반환 개선이 설계 품질을 자동 보장한다는 결론은 내리지 않았다.
- 제공 helper의 `JObject/JArray`와 파일 결과는 새 JSON-safe 직접 반환과 다른 경로다. 이 차이를 문서에 분리했고 실행 코드는 바꾸지 않았다. 실제 모델링 품질 비교는 이번 정합 작업에서 수행하지 않았다.

## 사례의 지침화 정정 — 2026-10-23

- 앞선 반영은 개별 작업에서 발견한 문제와 대응을 공통 검토 항목으로 강제한 부분이 있었다. 요구사항이 문서에 존재하는지만 확인해 충분히 반영됐다고 판단한 것도 부적절했다.
- `references/workflow.md`와 `references/visual-review.md`의 사례 열거를 현재 목적·조건에서 문제를 정의하고, 관찰과 가정을 구분하여 대응·검증을 선택하는 원칙으로 고쳤다. 반복 적용의 조건과 변경 영향도 그때의 과업에 따라 판단하게 했다.
- 개별 사례는 기존 세션 분석의 근거로 보존하며 공통 스킬에서 해결책을 강제하지 않는다. 실제 모델링 효과는 이번 문서 수정으로 입증하지 않았다.

## 고정 조회의 문서 보존 — 2026-10-23

- PR #4에서 helper 자체가 읽기 전용이어도 일반 C# 실행기가 Undo·AIA 레이어를 준비하는 문제가 지적됐다. 고정 probe 다섯 종류를 컴파일된 전용 API로 옮기고 기존 bootstrap·파일 결과 조립 경로를 제거했다.
