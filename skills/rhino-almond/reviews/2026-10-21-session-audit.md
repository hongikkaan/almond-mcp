# rhino-almond 세션 검토와 개선 근거 — 2026-10-21

## 결론과 범위

반복된 문제는 Almond 도구의 단순한 사용량 부족보다 **현재 기준의 해석, 재구축 방식, 공간과 접합의 실제 성립, 완료 근거의 범위**에 있었다. 도구 호출·등록·수치 검사만으로 사용자 요청을 충족했다고 판단한 구간이 있었고, 사용자가 그리드·레벨·구축 방식·공간 목적을 다시 지적한 뒤 방향이 수정됐다. 반면 한계를 밝힌 검증, 실제 단면으로 오류를 찾고 계획을 다시 연 과정, 독립 크리틱을 반영한 결과는 유효한 개선 사례다.

스킬은 실행 코드 교체 없이 핵심 지침과 관련 참조 문서를 보강한다. 편집 범위는 사용자의 최신 교정대로 **현재 열린 Rhino 문서와 해당 `.almond`뿐**이라는 규칙으로 명시한다. 여러 파일의 공유 DB에 추가 소유권 판단이나 다른 문서의 Scene 보호 규칙을 붙이지 않는다. 설계 논의·크리틱·고찰은 읽기 전용 subagent와 수행하며 실제 편집은 주 에이전트가 담당한다.

사용자 지시의 전체 목록과 시점별 변경은 [별도 지시 목록](2026-10-21-user-directives.md)에 정리했다. 두 파일은 유지보수 근거이며 일반 모델링 때 매번 읽도록 연결하지 않았다.

L4002/L4020 이후에는 공간 3F~RF 구축이 우선이고 구조해석은 뒤로 미루도록 요구가 바뀌었다. L4737의 기록은 새 유닛 62개/terminal cassette 31개와 연결부 미완료, native 조회 오류, 독립 subagent 두 번의 시작 실패를 밝힌다. L4742 실제 검사 출력은 기존 3,000개 루트 보존과 62/31개 수량, 구조해석 deferred, 실제 단면 6장 및 `interfaces_resolved: false`를 확인한다. 최종 L4776도 연결 오류와 미완료 항목을 보고했다. ‘자식 에이전트를 요청했으므로 독립 검토 완료’나 ‘유닛을 배치했으므로 공간 완성’으로 기록하지 않은 점은 보존할 행동이다.

### S6 — Terrain: 수치상 통과 뒤 실제 사용 상태로 돌아간 사례

닫힌 형상과 충돌 제거만으로 포장의 실제 노출 상태가 확보되지 않았다. L947의 단면 검토는 void/뜬 포장 문제를 찾았고, 이후 수정에 따라 검사를 반복했다. L3841에서는 resolve_collisions/final_validation을 다시 열었다. 형상·사용 조건이 바뀌어 수행한 이 재검증을 불필요한 반복으로 분류하면 안 된다.

최종 근거는 구체적이다. L3901은 2,203개 표본 ray에서 soil에 가려진 포장 0, L4105는 mesh의 indexed manifold/closed와 coincident-vertex manifold false를 함께 기록한다. L4116은 저장 형상 대조와 10,282개 ray 검사, L4210은 live asset 48개 일치를 확인한다. L4233은 topology 경고와 표현용 mesh 한계를 남겼다. 본 감사는 표본 0을 전체 공간의 수학적 무간섭 증명이나 토목 적합성으로 확장하지 않는다.

L4202의 실행 오류와 결과 미생성 뒤 L4206/L4210에서 회복한 구간도 있다. 실패→기존 파일 조회 위험을 줄이는 규칙은 필요하지만 최종 전체를 오류로 분류할 근거는 아니다. S6는 스킬 로드가 확인되지 않아 ‘스킬이 이 행동을 유발했다’는 인과 주장에도 사용하지 않는다.

## 사용자에게 드리는 피드백

사용자의 표현이 모든 실패의 원인은 아니다. ‘보고 새로 만들라’, ‘그리드에 맞추라’, ‘레벨은 슬라브 상면’, ‘공간을 이해하라’ 같은 요구는 이미 구체적이었고, 에이전트가 먼저 지켜야 했다. 같은 요구를 반복해서 강하게 말하게 된 원인도 이 불이행에 있다.

다만 시작 시 다음 네 가지를 한 문단으로 고정하면 재작업이 줄어든다. **이번 기준 모델/도면, 반드시 보존할 대상, 이번 상세 수준, 질문이 필요한 결정 범위**다. 예를 들어 ‘현재 Market Hall과 같은 수준’은 도구 운영 방식·설계 완성도·구조 방식 중 어느 것을 같게 할지 갈릴 수 있다. ‘같은 검토 수준으로 하되 구조 형식은 현 공간에 맞게 판단’처럼 한 문장만 보태도 해석 차이가 줄어든다.

‘빔·트러스는 다시 만들고 구조는 남겨라’처럼 포함 관계가 겹치는 요청은 삭제/보존 대상을 레이어·그룹·선택 객체로 한 번 확정하는 편이 좋다(S5:L164/L189). 이는 사용자가 모든 GUID를 정리해야 한다는 뜻이 아니다. 에이전트가 후보를 읽고 간단한 확인안을 제시할 책임이 있다.

작업 중 상세 수준이나 순서를 바꾸는 것은 정상적인 설계 과정이다. ‘이제부터 상세를 올린다’, ‘구조해석은 다음 단계로 미룬다’처럼 변경 시점을 밝힌 지시는 이미 도움이 됐다. 에이전트가 이전 조건을 계속 붙드는 대신 현재 계획과 완료 기준에 반영해야 한다.

‘세계 최고 수준’이나 ‘도구를 모두 파악하라’는 기대 자체보다, 그리드 정렬·상하층 연결·실제 사용 공간·이번 단계에서 남길 미검증을 완료 조건으로 제시하면 판단이 쉬워진다. 모든 도구를 실행하게 만드는 것보다 필요한 도구의 결과와 실제 모델을 대응시키는 것이 유효하다. 사용자에게 검사 설계를 전가하지 않도록 이 판단 책임을 스킬에 명시했다.

이번 유지보수에서도 편집 경계를 공유 DB 규칙으로 과도하게 확장한 초안이 있었다. 사용자의 교정 후 단순한 문서/폴더 경계로 줄였다. 이는 지시가 모호해서가 아니라 에이전트가 요구 이상의 정책을 덧붙인 사례다. 보고 빈도 교정 역시 현재 작업과 스킬에 직접 반영했다.
