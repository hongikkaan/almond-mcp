# 현재 rhino-almond 적용 세션 분석과 개선

## 분석 범위와 순서

기존 개선 초안을 먼저 원복했다. 현재 배포본의 본문 최종 수정은 **2026-10-21 20:13:15.002 KST**, 전역 복사 시각은 20:57:23.920, 대응 커밋은 `8806f9b`다. SKILL.md 단독 수정 시각은 20:13:14.999이며, 기준은 참조 문서를 포함한 마지막 본문 수정이다. 원복 때문에 바뀐 개발 파일 시각을 기준으로 쓰지 않았다.

접근 가능한 JSONL 116개(2,777,285,831 bytes)의 timestamp 색인에서 후보를 찾고, 실제 전체 스킬 주입/읽기 내용을 현재 배포본과 대조했다. 이름 언급·스킬 활용성 문서 검토만 한 대화·개발/Git/환경 작업은 제외했다. 상한은 **2026-10-22 11:56:47 KST**로 고정했다. 같은 UUID의 구버전 구간도 제외했으며, 현재 버전 로드를 촉발한 바로 앞 과업 요청은 지시 목록에 포함했다. [버전·전체 후보와 제외 근거](scope.json)

대상은 **논리 세션 9개, 적격 구간을 포함한 물리 로그 21개**다. 세션당 한 subagent가 재개·fork·관련 하위 검토를 연결해 공개 요청·호출·반환·수정·완료 흐름을 끝까지 검토했다. 주 agent는 최종 보고와 coverage를 대조하고 누락된 자식 도구 검토, 로드 직전 지시, Slack 발신 분류를 보완시켰다. 전 세션 분석·문제점 고찰을 마친 뒤 개선안을 정하고 문서를 수정했다.

## 문제점 고찰

1. **vision 사용 여부만으로 원인을 설명할 수 없다.** 실제 열람과 수정이 있었지만 내부를 가린 캡처, 실제 발밑 레벨과 맞지 않는 카메라, 불연속 경로·문·바닥·벽 접점이 놓쳤다. 캡처/등록 개수는 이 문제의 해결 증거가 아니었다. 반대로 B1F clipping 착시는 다른 표현과 방향을 대조해 불필요한 편집을 피한 사례다.
2. **부품 상세와 공간의 사용 조건이 분리됐다.** 가새·문·외피·cassette를 개별 생성해도 연속 보행·도착·지지·배수가 성립하지 않았다. 반복 상세는 일반 bay에서 맞더라도 끝단·코어·곡면 조건이 달랐다. 문제 부품 제거만으로 그 부품의 원래 기능까지 해결되지 않는다.
3. **메타데이터·계수와 실물의 대응이 약했다.** 보 이름의 치수와 실제 단면, 서로 다른 시점/열거 범위의 객체 수, 등록된 fixture/instance와 전체 모델은 구분해야 했다. 이를 전역 스킬의 특정 helper 결함이라고 결론낼 근거는 없었다.
4. **완료의 범위가 과장되거나 흐려졌다.** 저장·유효 solid·plan 상태·도구 바깥 성공·예비 구조 PASS는 각각 다른 사실이다. 최신 모델에서 실제 요청 조건이 확인됐는지, 미측정·생략·후보 제한·실패가 남았는지가 완료 판단에 필요하다. 기존 지침에도 이 구분이 있었으므로 동일 경고를 늘리기보다 구체적인 확인 동작과 연결했다.
5. **중단과 출처 확인에도 같은 구분이 필요했다.** 타임아웃/Undo 오류가 자동 롤백을 뜻하지 않았고, 후속 상태 대조가 회복을 증명했다. Slack 표시 이름은 발신 주체 증명이 아니었다. 실제 send/upload와 맞춰 자기보고를 제거했고, 원문 없는 사용자 답변 전달은 직접 승인으로 바꾸지 않았다.

## 지시 집계와 개선 판단

`steered.md`는 유사 지시를 합친 **35행의 표 하나**다. 138개 직접/전달 요구 레코드를 모두 행 또는 중복 제외 근거에 연결했다. 같은 발언을 여러 요구로 나눈 경우 같은 행에서 한 번만 세고, event/fork/readback 복제와 확인된 원문·전달 중복을 제거했다. 별도 실제 재입력과 별도 전달 기록은 세션 구분 없이 합산했다. 원 사용자 글이 없는 relay가 포함돼 있으므로 이 횟수는 기록상 관측 횟수이며 실제 원 사용자의 입력 횟수를 확정하는 값은 아니다. ## 검증 범위

문서 변경만 수행했다. 분석 산출물 JSON, 요구 기록 138개의 원본 행·직접 발언, 35행 집계와 누락 여부, 필수 요구 반영, 문서 링크 45개, 지침의 중복·충돌과 Git 공백 오류를 확인했다. 배포 목록은 SKILL.md·참조 7개·스크립트 5개의 13개 파일로 제한했다. 코드·기하 회귀 검사는 실행하지 않았다. 새 스킬의 효과는 실제 후속 Rhino 과업에서 평가해야 한다. 사용자 지시에 따라 이번 전역 교체용 추가 백업은 만들지 않는다.
