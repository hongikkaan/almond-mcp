# 시각 검수

## 검수 순서

1. **매 검수마다 여러 장소의 실제 눈높이 Perspective를 Named View로 저장하고, 각 뷰에 복수 Display Mode를 적용해 이미지를 직접 열어 검토하라.** 실제 사용 조건과 문제 부위의 관계를 판단할 수 있는 위치와 시점을 고른다.
2. **실제 clipping plane으로 자른 평면과 종·횡단면을 검수하라.** 위치·방향·범위는 현재 문제와 변경 영향을 확인할 수 있게 정한다. Parallel 뷰를 함께 쓸 수 있다.
3. 그 뒤 목적에 맞는 형상 측정·접합·구조·배치 검증을 수행한다. 시각 관찰과 수치 결과가 다르면 해당 객체와 검수 조건을 다시 확인한다.

## 화면 준비와 확인

평·단면의 주 모드는 **AGENT_Section_Glass**로 하고 Ghost_Xray·Dark·ALMOND 계열 등 현재 설치된 모드를 함께 사용하라. 이름은 실제 목록에서 확인한다. 요구한 모드가 없으면 누락과 사용한 대체 표현을 밝히고 해당 모드로 검수했다고 하지 마라.

뷰·모드·clipping을 준비한 뒤 현재 화면 한 장은 `get_rhino_viewport_image`의 실제 ImageContent로 바로 검토할 수 있다. 이 도구가 Named View 전환·절단·모드 적용까지 수행한다고 가정하지 마라. 반환 metadata로 문서·뷰·시점을 대조하고, 이미지가 직접 전달됐다면 검토만을 위해 파일을 다시 만들 필요는 없다. 기록·제출용 파일이 필요하면 artifact_dir에 별도로 저장하라.

## 종횡단면 전면검수 지시 시

**사용자가 종횡단면 전면검수를 지시한 경우에만** 다음 전 범위 검수를 수행하라. 사용자가 범위나 간격을 별도로 지정하면 그 지시를 따른다.

- 지정 대상의 종·횡 방향을 각각 1000mm 간격으로 이동하며 실제 clipping plane으로 자르고 검수한다.
- Z도 1000mm 간격으로 이동하며 평면을 자르고, Top과 반대 방향에서 모두 검수한다.
- 문서 단위를 확인해 환산하고 시작·끝 경계를 포함한다. 도면 추출이나 대표 단면 몇 장으로 이 전 범위 검수를 대체하지 않는다.

전면검수 지시가 없으면 일반 검수 순서에 따라 현재 문제와 변경 영향에 맞는 검수 범위를 정하라.

## 무엇을 확인할지

- 피드백 스케치는 해당 Named View와 현재 객체를 맞춰 해석한다. 과업의 목적·요구·설계 의도에서 확인할 관계를 정하고 실제 형상·수치와 대조한다. 객체 이름이나 부품 개수로 기능을 대신 판정하지 않는다.
- 판단할 관계가 이미지에 보이도록 시점·표시 조건을 조정하라. 표현에서 생긴 현상과 실제 형상 문제를 구분하고, 불분명하면 다른 시점이나 측정 근거로 대조한 뒤 형상 변경 여부를 결정한다.
- 중첩 객체는 [블록과 주석](blocks-and-notes.md)에 따라 경로·누적 변환으로 식별하고 확대·인접 관계 캡처를 함께 검토한다. 실제 편집 단계와 공유 정의 영향도 확인한다.
- 이미지별로 확인한 현상과 대상·위치, 수정 또는 미해결 판단을 짧게 남긴다. 생성·업로드·manifest 수량만으로 이미지 내용을 검토했다고 하지 마라. 수정한 곳은 같은 위치에서 다시 보고, 바뀐 형상의 영향 범위도 재검수한다.

검수 기록에는 모델/실행 시점, 뷰·모드·절단 위치와 관찰 결과를 연결하라. 미열람·가려짐·누락된 구간은 완료로 표시하지 않는다. 최종 시각자료는 전체 관계와 문제 부위 확대를 읽을 수 있게 취합하고, 실제 형상·저장·등록의 완료 근거는 [작업 지침](workflow.md)과 함께 확인하라.
