# 피드백 요청·최종 보고

Step의 결과를 사용자에게 보여 주거나 피드백을 반영하고 작업 자료를 정리할 때 적용한다. 통신 채널·수신자·승인 방식은 사용자가 정한 작업 지침을 따른다.

## FR1. 결정에 필요한 내용을 함께 전달한다

질문, 대상 위치와 해당 결정에 필요한 비교 그림·선택지, 추천 이유와 결정을 바꾸는 조건을 하나의 읽기 흐름 안에 둔다. 사용자가 직접 표시하거나 다른 방향을 제안할 수 있도록 대상 식별과 필요한 해상도를 확보한다. 실제 전달 크기에서 읽어 보고, 핵심 관계가 읽히지 않으면 주도면과 보조 자료로 나눈다. 도면·질문의 개수를 기계적으로 고정하지 않는다.

조회·측정으로 확인할 사실은 작업자가 먼저 확인한다. 사용자에게는 설계 방향·범위·중요한 선택을 묻는다. 선택에 영향을 주는 미확인을 짧게 드러내고, 도구 실행 내역은 필요한 근거로 분리한다. 대안 자체의 시각 비교는 `design_exploration` policy를 따른다.

## FR2. 답변을 해당 제안과 범위에 연결한다

회신이 어떤 설계안·그림·조건을 가리키는지 확인해 현재 Plan의 판단과 연결한다. 일부 경계나 한 안의 승인으로 다른 Scene·상세·대안까지 승인됐다고 해석하지 않는다. 범위 축소·중단은 그 범위의 결정이며 미검증 품질의 승인이 아니다. 답변이 불명확하면 영향을 받는 결정만 확인하고 독립적으로 진행할 수 있는 작업은 이어간다.

같은 조건에 이미 받은 승인은 재사용한다. 새로 달라진 중요한 조건이 있으면 그 차이와 영향을 설명한다. 회신 부재를 승인으로 해석하거나, 최종 보고마다 불필요한 승인 질문을 추가하지 않는다. Plan 완료 결정은 기존 Plan 안내를 따른다.

## FR3. 전달할 결과와 남길 근거를 구분한다

사용자의 목표에 대해 달성한 결과를 해당 파일·도면·이미지와 연결한다. BASIC의 보고 기준을 적용하며, 사용자가 전달물을 다시 열어 결과와 판단 근거를 찾을 수 있도록 대상·버전·참조 경로를 맞춘다.

정리 Step에서는 현재 과업이 만든 중간 객체·파일 중 더 이상 쓰지 않는 것만 정리 대상으로 삼는다. 기존 모델·참조 자료, 비교·재현·사용자 결정에 필요한 근거와 선택되지 않은 안의 보존 필요성을 먼저 확인한다. 정리로 보존할 결과·참조 경로가 손상되지 않았는지 확인한 뒤 최종 결과를 연결한다.
