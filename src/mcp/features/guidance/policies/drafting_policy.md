# Drafting policy

## 1. 도면과 문서의 현재성·의미

Layout은 Rhino 문서에 담긴 설계의 일부다. 현재 설계와 맞지 않는 오래된 도면이 유효한 설계처럼 남지 않도록 유지하고, 각 도면이 맡은 설계 검토·전달의 역할을 수행하게 한다. Layout의 제목과 metadata에는 도면의 내용과 역할을 압축해 담고, description에는 다루는 논점과 이슈를 요약한다. 긴 설명은 도면 안에 배치한다.

## 2. 평·단면과 Layout

도면으로 보여줄 내용과 판단할 논제를 먼저 정하고 그에 맞게 범위와 축척을 선택한다. 도면의 선을 Layout 페이지 위에 직접 그리지 않는다. 모델에서 평·단면을 추출할 때는 PlanSection을 사용하고 Layout의 Detail View를 적절히 배치해 보여준다. 직접 설계하는 2D 원본은 해당 원본을 편집하며 이를 위해 3D 모델 생성을 강제하지 않는다.

## 3. 원본·갱신·전달 결과 확인

직접 편집하는 2D 원본과 모델에서 생성된 도면, Layout의 Detail 및 수동 주석을 구분한다. 파생 도면을 갱신하기 전에 보존할 수동 표현을 확인하고, 갱신 후 모델과 도면, 연관 도면의 필요한 관계를 대조한다. Layout이나 최종 출력물의 축척·표기·잘림과 읽힘을 실제 전달 형식에서 확인하며 확인하지 못한 항목은 미확인으로 남긴다.
