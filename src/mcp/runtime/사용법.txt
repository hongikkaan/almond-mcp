Almond — 시작과 정리

현재 연결은 storage_protocol=2와 기존 A–J 슬롯(5501–5510)을 사용합니다.
protocol 번호는 실행기와 호스트가 자동으로 처리하며 사용자가 설정하거나 별도 승인할 필요가 없습니다. 이미 정상 연결된 세션은 그대로 계속 사용합니다.
RhinoTerminal은 src/rhp/RhinoAlmondBridge/plugin-runtime/RhinoAlmondBridge.rhp에 포함되고, AlmondRhino는 src/rhp/AlmondRhino/plugin-runtime/AlmondRhino.rhp를 사용합니다.
새 RHP와 같은 폴더의 Almond.Engine.dll 등 의존 파일, 새 Python worker가 모두 필요합니다. 작업을 마친 뒤 정상 재시작해 적용합니다.

Rhino 내부 패널에서 사용: 저장된 모델 열기 → RhinoTerminal On → PanelToggle로 패널 표시 → almond 입력 또는 우측 상단 almond 버튼.
이 방식은 새 Rhino를 띄우지 않고 현재 문서에 연결합니다. Codex의 /exit로 연결 해제를 요청합니다.
아래 「Almond 시작」은 별도 Rhino와 외부 터미널을 여는 기존 방식입니다. 같은 Rhino를 두 연결이 동시에 소유할 수는 없습니다.

Rhino 내부 패널에서 이전 대화 이어가기
  Codex에서 /exit → PowerShell에서 almond resume → 이전 대화 선택.
  ID를 알면 almond resume <대화 UUID> 형식으로 입력합니다.
  현재 Rhino 문서의 DB/TEMP/연결로 다시 시작합니다. 현재 모델에 해당하는 대화를 선택하세요.
  Codex 안의 /resume은 기존 MCP가 잠금을 보유한 상태에서 새 MCP를 만들어 충돌합니다.
  Codex 종료 화면의 codex resume 대신, 이 패널에서는 almond resume를 사용하세요.
  새 대화는 기존처럼 almond입니다. 목록은 Enter로 선택, Ctrl+C로 취소합니다. Esc는 새 대화입니다.
  구버전 RHP가 메모리에 남아 있으면 작업을 마치고 해당 Rhino를 정상 재시작하세요. 새 worker도 필요하며, beyond·CoS는 해당 MCP 프로세스를 정상 종료·재시작한 후 다시 연결합니다.

1. 작업할 .3dm을 먼저 저장해 두세요. 새 모델도 일반 Rhino에서 한 번 저장하고 닫습니다.
2. 「Almond 시작」을 더블클릭하고, 파일 선택창에서 작업할 .3dm을 고릅니다.
3. 그 파일이 열린 Rhino와 Codex 대화창이 자동으로 뜹니다. Codex에 한국어로 작업을 요청하세요.
   .3dm을 「Almond 시작」 위로 끌어다 놓아도 됩니다. 원본 보존이 필요하면 복사본을 선택하세요.

추가 작업도 「Almond 시작」을 실행합니다. 문서 전용 CLI·RhinoTerminal·beyond·CoS가 최대 10개 A–J/5501–5510 슬롯을 함께 사용합니다.
같은 폴더의 여러 모델을 각각 다른 Rhino/포트로 연결해 공통 DB/tmp를 사용할 수 있습니다. 같은 Rhino·포트·슬롯의 중복 연결은 차단합니다.
외부 실행기 끝내기: 진행 중인 작업 완료 → Rhino에서 Ctrl+S → Codex 정상 종료 → 해당 Rhino 정상 종료.
작업 중에는 다른 .3dm을 열거나 Save As를 하지 마세요. 연결을 해제한 뒤 문서를 바꾸고 다시 연결합니다.

저장 위치
  프로젝트\UNIT.3dm
  프로젝트\.almond\scene.sqlite3                   ← 모델 폴더의 공통 DB
  프로젝트\tmp\261026_적절한이름\                 ← Plan이 소유하는 산출물
  프로젝트\.almond\.sessions\<token>\             ← 연결 기록과 역할 잠금
  프로젝트\.almond\.sessions\store.lock           ← 공통 DB 잠금
  프로젝트\.almond\tmp\python\<token>\<operation>\ ← 필요할 때만 만드는 임시자료
모델 이름·슬롯을 바꿔도 같은 폴더의 DB 위치는 같습니다. 기존 확장자 없는 DB는 다른 worker가 사용하지 않을 때 checkpoint 후 scene.sqlite3로 이름을 바꾸며, 충돌 시 양쪽 파일을 보존합니다.
Codex 작업 폴더와 ALMOND_PROJECT_ROOT는 .3dm이 있는 프로젝트 폴더입니다.
project_info는 project/document/artifacts를 기본으로 조회하며 document에 live 확인 결과가 포함됩니다. sections로 필요한 항목만 고릅니다.
set_working_plan으로 작업을 선택하면 Plan의 산출물 폴더를 재사용합니다. execute_project_python은 그 폴더에서 상대경로로 실행합니다. Rhino C#은 ManagedFiles.Input/Output에 상대경로를 전달합니다.
rename_artifact_folder로 폴더명을 바꾸면 현재 Plan/Step 자료 참조도 갱신합니다. 과거 revision은 그대로 남습니다.
작업은 paused 등 미완료 상태에서 중단·전환·재개할 수 있습니다. Plan 완료는 임시자료 정리 조건이 아닙니다.

공용 원본 라이브러리
  에셋·GH·캡슐·재료·구축 자료는 기본적으로 %LOCALAPPDATA%\Almond 아래에서 읽습니다.
  예: %LOCALAPPDATA%\Almond\DrawingAssetfiles
  GeneratedAssetfiles와 Draftingfiles는 각각 releases\0.7.0rc2 하위 폴더를 사용합니다.
  사용자가 RHINO_MCP_*_DIR로 별도 경로를 지정했다면 그 설정을 존중합니다.
  Python 환경은 src/engine/.venv에 있습니다. 설치 패키지의 almond_mcp/data는 배포용 원본이며 사용자 라이브러리가 아닙니다.
  DB/tmp는 모델 폴더 단위로 공유하고 연결 기록·호출 출력만 분리합니다. 10개 라이브러리의 기존 위치·내용·선택 순위·override·releases 규칙은 유지합니다.
  라이브러리 변경은 MCP를 새로 시작해 반영합니다. protocol 2 적용에는 새 RHP/Almond.Engine.dll도 함께 필요합니다.
  Rhino 내부 패널: Codex에서 /exit → PowerShell에서 almond 또는 almond resume.
  외부 실행기: 작업을 저장하고 기존 전용 세션을 종료한 뒤 「Almond 시작」을 다시 실행합니다.
  .almond 폴더·DB·잠금 파일을 임의로 삭제하지 마세요. 시작 색인은 공통 store.lock 아래에서 기존 DB에 갱신합니다.
  다운로드하지 않은 외부 모델은 경로가 올바르더라도 계속 사용 불가로 표시됩니다.

tmp 정리
  프로젝트 tmp/YYMMDD_name 산출물은 작업 완료만으로 자동 삭제하지 않습니다.
  .almond/tmp/python의 호출 임시자료는 코드/native 완료 확인 후 회수하고 빈 상위 폴더도 제거합니다.
  .sessions의 종료된 token 기록은 worker 종료 또는 다음 시작 시 프로세스 identity·잠금을 확인해 회수합니다. 사용 중이거나 native 완료가 확인되지 않은 연결 자료는 보존합니다. 이는 Plan/Step 완료 여부와 무관합니다.
  기존 .almond/tmp에는 과거 산출물도 있으므로 일괄 삭제하지 않습니다.
  관리형 Python 실행의 자식 프로세스는 실행 종료 시 함께 종료합니다. 원래 Rhino 프로세스 TEMP와 사용자 라이브러리는 유지합니다.

이름을 바꿀 때
  해당 연결의 실행을 중지하고 패널은 /exit, 외부 Codex·CoS 연결은 almonddisconnect로 해제를 완료하세요.
  외부 실행기로 연 세션은 모델을 저장하고 Codex와 해당 Rhino를 정상 종료하세요.
  같은 폴더에서 UNIT.3dm을 HOUSE.3dm으로 바꿔도 .almond와 DB의 위치는 그대로입니다.
  HOUSE.3dm에서 새로 연결하면 기존 공통 DB와 tmp를 이어 씁니다. .almond 안에 모델명 폴더를 만들거나 이름을 맞추지 않습니다.
다른 위치로 옮길 때: 그 .almond를 공유하는 모든 실행 중지 → 모델들 저장과 모든 연결·해당 창 정상 종료 → 모델들과 .almond 전체를 같은 새 로컬 폴더로 이동합니다.
새 위치의 .3dm을 열고 RhinoTerminal → almond 또는 almond resume로 시작하면 현재 경로로 다시 연결합니다.
이름도 바꾸더라도 공통 .almond 폴더와 DB 이름은 유지합니다. 기존 기록을 자동 병합하거나 초기화하지 않습니다.
.almond를 함께 옮기지 않으면 기존 DB를 이어 쓸 수 없습니다. 파일명/경로가 적힌 과거 코드·기록은 자동 수정되지 않습니다.
공용 에셋, 외부 텍스처/참조 파일, Codex 대화 기록은 .almond 이동에 자동 포함되지 않습니다.

src/mcp/runtime은 실행기 소스입니다. src/engine/.venv의 Python 환경은 src/mcp/rebuild_environment.ps1로 uv.lock에 맞춰 구성합니다.
이전 src/engine의 시작 버튼도 새 실행기를 호출합니다. 일상 업데이트는 연결을 끝내고 Rhino 정상 종료 → 일상 폴더에서 pull → Rhino 시작이며 beyond·CoS MCP도 정상 종료·재시작 후 다시 연결합니다.
작업 모델의 .almond는 공통 데이터와 연결 기록이므로 모델과 함께 관리하세요.
오류가 나오면 설정을 바꾸지 말고 창 전체를 캡처해 전달하세요. 네트워크 드라이브는 지원하지 않습니다.

프로세스가 남았을 때 — 「Almond 정리」 더블클릭
  1 또는 Enter: 남은 보조 프로세스만 정리. 열린 Rhino·Codex는 유지합니다.
  2: 확인된 Almond 작업을 모두 종료. Codex는 종료하고, Rhino 저장창은 직접 처리합니다.
  3: 전체 강제 종료. 멈춘 작업에만 사용하세요. 미저장 모델을 잃을 수 있습니다.
종료할 목록을 확인하고 화면에 요구된 단어를 입력해야 실행됩니다. 0은 취소입니다.
작업 중에는 쓰지 마세요. 먼저 저장하세요. DB·tmp·3dm 파일은 어떤 메뉴도 삭제하지 않습니다.
이 설치에서 실행한 것으로 확인된 대상만 정리하며, 일반 Rhino·Codex와 소속 불명 프로세스는 건드리지 않습니다.
