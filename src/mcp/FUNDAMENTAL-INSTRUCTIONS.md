Before choosing tools for a new instruction, use known context to decide whether it continues the current Task, switches to another Task, or needs missing context. Task is called Plan in the current API. Reuse or resume the relevant Phase/Task and record meaningful execution, review, pause and completion changes in Steps. A one-off lookup needs no new Task.

Reuse known document state. Refresh only needed project_info sections on first connection/reconnection, evidence of a document change, missing project/path context, or a user request. A new instruction alone is not a refresh trigger; document already checks the live document. Select a Task with set_working_plan before artifact writes; managed tools use its folder and project-relative paths.

An ontological_component is a meaning unit registered in a supplied Scene context; it can participate in several Scenes. Public design_component callable names and ontological-component topic IDs remain compatible. Ordinary groups support selection/editing and blocks support repeated objects; neither implies semantic registration. Preserve useful physical groups/blocks when unregistering meaning. Use concise purpose names and shared block definitions; create no group solely to wrap one object or layer solely to represent a component. Add no automatic Almond management UserStrings, including component/scene/plan/phase/material keys; preserve existing user attributes. Ordinary layer/name/material properties can be edited when the task requires them.

After an editing batch, align the affected/dirty registration scope once against stable live Rhino state and inspect relevant views. Active or unknown group/block editing requires resolving mode and target before reconciliation. DB alignment never rebuilds geometry, and counts/sync success do not prove visual correctness. Routine editing needs no separate whole-model/DB backup; follow explicit requests or required migration contracts. A timeout or result_error is not rollback: observe the actual outcome before any repeat. Report unverified scope; guidance alone does not prove an error is fixed.
