# Dashboard host offline contracts

This fixture compiles `DashboardPanel.cs` against the installed Rhino/Eto SDK, but never constructs a panel, starts Rhino/RhinoCore, or opens a model or database. Its executed contracts use a fake child process at the launcher boundary to cover checkout-bound source and Python resolution, missing Python, child environment and CLI arguments, duplicate opening, address/token validation, navigation origin isolation, failed startup and close during startup.

An inherited embedded-Python environment fixture checks that the external Dashboard child receives none of `PYTHONHOME`, `PYTHONPATH`, or `PYTHONEXECUTABLE`, while unrelated settings and the parent process environment remain unchanged.

Current-document selection uses placeholder `.3dm` files and disposable arbitrary byte files at project DB paths. It checks existing project resolution without an MCP connection, missing/deleted/read-inaccessible DB, document/project switch, explicit command reselection, byte preservation and no session allocation. Neither Rhino nor SQLite opens these placeholder files.

Run this Dashboard-only fixture with `dotnet run --project src/rhp/Asset_Panel/tests/DashboardHostContracts -c Release`. A different SDK directory may be passed to the fixture build as `-p:RhinoSystem=<Rhino System directory>`.

The real entry point after a separately authorized runtime build/deployment is `AlmondDashboard`. Rhino’s default command discovery finds the public command class, and the first invocation registers and opens its panel. The feature owns its app-close cleanup. The fixture validates the command's SDK type and hook metadata without loading Rhino. An optional first argument to the fixture DLL verifies that metadata in the built Bridge RHP too. The panel runs the same read-only Dashboard server with the current document's existing project DB. Explicit reopening reselects the current project after a manual file choice. Document activation/save/close refreshes context; unsaved/missing/inaccessible projects clear the previous viewer and display a status without creating a DB. Closing the last panel or shutting down the plugin stops only its owned child process tree. Hidden panels keep their viewer session. Actual Rhino display/loading and the Windows DB file picker are outside this fixture's verification scope.
