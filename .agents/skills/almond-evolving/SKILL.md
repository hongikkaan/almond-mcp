# Almond Evolving
라이노 편집 툴인 almond-mcp와 그것을 활용하는 rhinobeyond스킬 2개를 같이  evolving하는 스킬이다. 툴을 사용한 여러 세션의 로그를 바탕으로 개선안을 구상하고 협의한 후, 개선을 수행한다.

참고: 분석 대상인 rhinobeyond스킬 및 almond-mcp툴을 사용한 세션은 사용자가 직접 진행한다.

## 1. 세션 로그 분석

진행 중인 세션은 현재까지의 로그를 분석한다. 다시 분석할 때는 앞서 분석한 지점부터 현재까지 이어서 보고, 세션이 끝나면 전체 로그를 다시 고찰한다.

1. 툴을 사용하는 세션이 진행 중인 경우

   원본 로그에서 당시 지침, 툴 호출·응답, 산출물을 대조해 무슨 일이 있었고 왜 그렇게 됐는지 판단한다. 그다음 익환의 별도 피드백과 인박스를 같은 로그에 대조해, 판단이 달라진 부분과 그 이유를 적는다.

2. 툴을 사용하는 세션이 모두 끝난 경우

   - 전체 로그를 익환의 피드백과 [Almond Actions](https://app.notion.com/p/81d601b1051c4eacad958a136083c723) 등 관련 인박스와 대조한다. 같은 문제는 묶고, 이미 조치한 문제는 개정판을 실제로 쓴 세션에서 다시 발생했는지 확인한다.
   - 설계 결과와 툴 사용에서 확인한 문제를 구분해, 회차의 기존 Notion Evolving Action에 [회고 양식](references/notion-wrapup-template.md)으로 세션별 근거와 함께 남긴다.

## 2. 개선안 작성

개선할 사항 정의 내용을 담을, 후속 논의에서 쓸 `FIXING.md` 작성
-  [검토안 양식](references/review-template.md)으로 저장소 루트의 `FIXING.md`를 작성한다. 같은 회차 문서가 있으면 재사용하고, 이전 회차 문서가 남아 있으면 해당 회차와 현재 변경 상태를 확인한 뒤 새 회차로 갱신한다. 기대한 동작과 관찰한 결과가 어디서 갈렸는지 적는다. 그 근거가 없으면 관찰한 현상과 남은 질문까지만 쓴다. 한 세션의 시행착오를 모든 설계에 적용할 규칙으로 만들지 않는다.

## 3. 개선안 논의

익환이 논의하자고 하면 저장소 루트의 `FIXING.md`를 보면서 논의한다.

## 4. 스킬·툴 설명 개선

`FIXING.md`에서 합의한 내용을 바탕으로, 익환과 함께 논의/수정하며 스킬·툴 설명을 개선한다.

## 5. 코드 개발 작업

`FIXING.md`에서 합의한 개선사항 중 코드 관련 항목을 구현한다.

### 역할

**동지**는 코드 개발 작업을 주관한다. Evolving의 출발점인 세션 로그, 그 이전의 프로그램·툴 개발 과정, 익환과의 협의 맥락을 가지고 있다. 그 맥락과 오늘 완수해야 하는 것을 정확히 인식하고, Codex 세션에 작업을 위임한다. 세션과 논의하면서 작업을 스티어링하고, 개발 작업을 완수할 때까지 오케스트레이트한다.

**Codex 세션**은 실제 개발 작업을 오케스트레이트한다. 서브에이전트에게 작업을 지시하고 검수·감독한다. 동지에게 보고하며 작업을 조율하고, 충돌 사항이나 결정할 일이 있으면 동지에게 논의를 요청한다.

### 작업 방식

동지가 최신 브랜치를 기준으로 `dev` 브랜치를 준비한다. 워크트리는 만들지 않는다. Codex 세션에 `FIXING.md`와 필요한 추가 자료를 전달하고, 아래 메시지를 보낸다.

> RhinoBeyond 스킬과 Almond MCP를 개선하는 작업에서 너는 코드 변경 작업을 주관한다. `FIXING.md`의 코드 개발 항목은 오늘 완수해야 할 사항이다.
>
> `grill-with-docs` 스킬로 동지와 논의하며, 목표 중 실현 불가능한 것이나 충돌을 찾아 명세를 조정한다. 이 조정은 `FIXING.md` 자체를 고치는 것이 아니다. 실현 가능한 목표를 정한 뒤 `to-ticket`을 실행한다. 그 결과에서 맞춰야 할 사항은 동지에게 논의를 요청한다. `implement-ticket`으로 작업을 수행하고 오케스트레이트한다. 동지와 논의해 목표·공개 동작·검수 기준을 바꾸기로 했다면, 바뀐 내용과 이유를 `FIXING.md`에만 남긴다.
>
> Rhino 실사용 검수는 Codex 세션 오케스트레이터만 한다. Computer Use는 사용하지 않는다. RhinoBeyond 툴의 실행·연결 기능으로 Rhino를 실행해 문서를 열고 연결한다. 이 경로로 조작할 수 있을 때만 실사용 테스트를 한다. 안 되면 실사용 테스트는 하지 않고, 할 수 있는 테스트만 해서 구현한다.
> 원격에 푸시하지 않는다.
> `FIXING.md`의 코드 개발 항목 중 구현할 수 있는 것은 모두 다 해야 한다. 구현하지 못한 것은 정확하게 밝힌다.

### 작업 종료

 동지는 `FIXING.md`의 코드 개발 항목 중 구현할 수 있는 것은 모두 다 했음을 코덱스 세션과 서로 동의할 때 작업을 끝낸다. 
 구현하지 못한 것은 정확하게 밝힌다.

## 6. Wrap up
