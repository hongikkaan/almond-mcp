# 설계 세션 개선 검토안

안건 하나에 아래 블록을 한 번 쓴다. 제목에는 로그에서 일어난 일을 적는다. 근거 줄은 사실을 찾을 수 있는 위치다. 어떻게 고칠지는 합의 전에는 `(제안)`, 합의 후에는 `(합의한 사실·정의)`에 쓴다. 결정·문구·시험은 문장마다 성격에 맞는 표지 하나로 시작한다. 적용되지 않는 줄은 최종 검토안에서 생략한다.

## 〈안건 번호〉 · 〈어느 상황에서 어떤 결과가 나왔는지〉

- **세션·근거** — 〈세션·Plan·Loop 중 식별에 필요한 것〉 · 〈로그 시각·도구 호출·익환의 발언 위치〉 · 〈관련 전후 도면·모델 판본과 달라진 점〉
- **관련 피드백·인박스** — 〈해당 원문 링크와 후속 결정·기존 조치 근거. 겹치는 기록은 한 안건에 연결하고, 부분 반영이면 남은 범위만 적는다.〉
- **문제 정의** — 〈익환이 말했거나 기존 합의·도면에서 확인한 기대 동작〉 / 〈실제 결과와 그 영향〉
- **재발 여부와 근거** — 〈같은 현상의 이전 기록, 당시 조치·적용 판본, 이번 결과〉
- **변경 위치** — 〈스킬·미니워크플로우 / 툴 description·입출력 주석 / 코드 중 바꿀 곳과 해당 파일·도구·필드〉

(제안) 〈아직 합의되지 않은 해석이나 해결 방법, 그렇게 판단한 이유. 익환의 결정이 필요하면 무엇이 달라지는지 함께 적는다.〉

(합의한 사실·정의) 〈익환과 확인한 의미·기대 동작 또는 결정한 해결 방법. 기존 동작을 유지하거나 관찰만 하기로 한 결정도 여기에 쓴다.〉

(삽입할 지침 문구) 〈합의 후 지정한 위치에 그대로 넣을 문장. 편집자에게 하는 설명은 빼고 실제 독자에게 쓴다.〉

(재시험 계획) 〈어떤 판본·입력·상황에서 다시 시도하고, 무엇을 관찰하면 통과인지. 필요한 경우 실패·반복 호출도 구별한다.〉

해석이 남아 있는 기대 동작은 ‘해야 한다’로 단정하지 않고 `(제안)`에 둔다. 과거 자료를 확인했지만 재발 여부를 가릴 수 없으면 확인한 범위와 ‘판단 유보’를 적는다. 원인이나 재발을 추정해 채우지 않는다. 코드 수정만 있는 안건에서는 삽입 문구 줄을 생략한다. 관찰만 하기로 했다면 변경 위치도 생략하고, 다시 볼 조건을 재시험 계획에 적는다.
