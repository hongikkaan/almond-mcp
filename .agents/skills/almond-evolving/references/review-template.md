# 설계 세션 개선 검토안

검토안은 기본적으로 스킬 개선, Tool description/schema 주석 개선, 코드 개발로 나눈다. 스킬에 넣을 작업 지침, 도구 설명과 필드 주석, 실제 동작이나 스키마 구조를 바꾸는 구현을 구분한다. 같은 문제가 여러 영역에 걸치면 해당 변경만 각 섹션에 적고 문제 설명을 반복하지 않는다. 일부 변경을 먼저 적용한 뒤 원복·재검토하는 회차처럼 적용 여부가 중요한 경우에만 적용 여부로 나눈다.

안건 제목은 `<문제 상황> : <해결 방안>`으로 쓴다. 왼쪽에는 관찰로 확인한 개선 대상, 오른쪽에는 구체적으로 만들거나 바꿀 것을 쓴다. 개별 로그 장면, 추정한 원인, 스킬·툴·코드 같은 분류명으로 대신하지 않는다. 둘 다 하기로 한 조치를 하나로 줄이지 않는다.

안건 본문은 항목이나 표지로 나누지 않고 필요한 만큼 일반 문단으로 쓴다. 처음에는 문제를 이해하는 데 필요한 설명과 해결 제안을 쓰고, 논의한 뒤에는 같은 문단을 최신 결론에 맞게 고친다. 미결이면 무엇을 더 확인해야 하는지 문장으로 밝힌다. 삽입 문구가 필요하면 그대로 인용하고, 재발이 확인된 경우에만 그 사실을 본문에 쓴다. 제목이면 충분한 안건에는 본문을 억지로 만들지 않는다. 기각한 안과 별도 검토 순서는 싣지 않는다.

판단 근거가 필요한 안건에는 해당 세션·호출과 피드백 원문, 기대·관찰 결과를 연결한다. 합의한 기능과 검수 기준은 실제로 확인할 입력·판본·결과와 함께 남긴다. 일부만 반영됐으면 남은 범위를 같은 안건에서 추적한다.
