# 설계 세션 심층고찰 · Notion Action

해당 회차의 기존 Evolving Action 한 곳에 회고를 남긴다. 아래 구성은 세션별 섹션 안에서 반복하고, 공통 쟁점은 각 세션 근거를 연결해 한 번만 정리한다. 아래 항목 중 근거가 있는 것만 쓰고, 중요한 미확인은 그 이유를 표시한다. 이 기록은 관찰과 분석이다. 익환에게 검토받을 개선안과 삽입 문구는 [검토안 양식](review-template.md)을 사용한다.

## 결과와 남은 문제

- **대상·최종 상태:** 세션 링크, 모델·Plan·Loop, 마지막 저장·산출물·검수와 미결 사항. 도구 성공, 실제 형상·시트, 저장본 재확인은 각 근거가 있는 범위에서 구별한다.
- **주요 전환:** 에이전트가 한 일 → 실제로 달라진 모델·도면·판단. 대조할 발언 시각, 로그 위치, 전후 도면·모델 판본 또는 링크를 붙인다.
- **1차 로그 분석:** 피드백을 열기 전에 기록한 결과·판단·반례·미확인. 이미 피드백을 본 경우 그 한계를 밝힌다.
- **2차 대조와 재고찰:** 피드백·인박스가 새로 드러낸 사실, 1차 판단에서 유지·수정·유보한 내용과 그 근거. 원문과 동일한 장면의 로그·산출물을 연결한다.

## 툴 사용 검수

**실행 기준선:** 세션의 실제 호스트 경로(beyond·RhinoTerminal 등)와 사용 판본을 남긴다. 당시 `tools/list`, 실제 읽은 도구 설명·스키마, 호출 응답, 클라이언트·호스트 설정 또는 로드 기록을 근거로 한다. 당시 등록되어 있었는지, 에이전트가 설명을 읽었는지, 현재 저장소에서 동일 기능을 확인했는지는 별개다. 스킬·서버·실제 로드된 RHP 판본은 각각 확인된 만큼만 쓴다.

의미 있는 사례마다 아래 블록을 반복한다.

### 〈사례: 어떤 호출이 어떤 결과로 이어졌는지〉

- **로그 근거·작업 의도:** 〈시각·줄·호출 ID와 목적〉
- **실제 호출 순서와 결과:** 〈입력·범위 → 응답 → 재호출/대체 → 실제 모델·도면·저장 결과〉
- **당시 가능했던 경로:** 〈후보 도구·계약, 같은 대상·범위·결과를 지원했는지와 그 근거〉
- **영향·비용·미확인:** 〈관찰된 지연·횟수·재작업, 관찰 범위와 미확인 사항〉
- **판정:** 〈사용 지침 / 기존 툴 개선 / 새 툴 후보 / 정당한 스크립트·복구 / 판단 유보〉

- 원본의 호출·응답을 순서대로 따라간다. 같은 상태를 중복 조회했는지, 과하게 넓은 범위나 대량 출력을 썼는지, 대상·판본·입력이 달라 필요한 재확인이었는지 구분한다. timeout·연결 불명·DB 잠금은 미실행이나 롤백과 동치가 아니다. 복구 전후의 문서·연결·요청과 실제 반영 여부를 대조해 필요한 복구와 불필요한 재시도를 가른다.
- **사용 지침:** 당시 공개 도구가 필요한 범위와 결과를 지원했는데 선택·입력·검증이 어긋났다. **기존 툴 개선:** 기존 도구의 계약·동작·출력 때문에 같은 작업의 호출·해석·복구가 어려웠다. **새 툴 후보:** 현재 도구로 같은 결과를 얻기 어렵고, 작업의 반복이나 관찰된 비용이 별도 기능을 검토할 근거가 된다. **정당한 스크립트·복구:** 필요한 형상·판단 범위가 전용 툴로 충족되지 않았거나 정상 상태로 돌아가기 위해 필요했다. 우회라는 이유만으로 결함으로 분류하지 않는다.
- **판단 유보:** 당시 노출된 도구, 입력·응답, 적용 판본 또는 결과 근거가 부족해 판정할 수 없으면 부족한 증거와 확인 가능 범위를 적는다. 확인한 범위에 조치할 문제가 없었으면 그렇게 적고, 로그가 없어 확인하지 못했다면 로그 미확보를 따로 표시한다.
- 도구 호출 수를 비용과 동일시하지 않는다. 같은 종류의 파악 가능한 호출을 기간·기준과 함께 세고, 지연·재작업·토큰·비용은 실제 기록에 있는 항목만 적는다. 가설상의 단축 시간이나 비용은 실측으로 쓰지 않는다.
- **후속:** 개선 후보마다 근거 링크, 남은 확인, 다음에 대조할 입력·판본·통과 기준을 남긴다. 비교 사례와 미확인을 명시하고, 검토할 항목만 루트 개선안에 연결한다.
