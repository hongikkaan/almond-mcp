# 도면 제작·검토(Layout·Detail)

Layout은 도면을 구성하는 시트이고, Detail View는 그 안에서 모델이나 도면의 특정 범위를 보여주는 창이다. Layout과 Named View는 설계의 일부다. 제목과 메타데이터에 내용과 역할을 압축하고, Layout의 description에는 검토 논점과 이슈를 요약한다. 동선·접합·공간 변화는 도면에 보이게 하고, 설명은 도면만으로 알 수 없는 결정과 미결 사항에 쓴다.

1. **열기 또는 구성.** 무엇을 보여주고 판단할지에 맞춰 범위와 축척을 정한다. 기존 Layout·Detail이 검토 범위와 축척을 담으면 재사용한다. 확대도가 주변 동선이나 접합을 잘라내면 전체 평면이나 단면을 함께 둔다. 프로젝트에서 지정한 용지와 축척에서 읽히도록 필요한 만큼 시트를 나눈다.
2. **문제가 생긴 곳에서 수정.**
   - **PlanSection으로 추출한 도면.** 모델에서 평·단면을 요구하면 `drawing_06-generate_plan_section` tool로 추출한다. 형상은 원본 모델에서, 단면 채움은 원본의 SectionStyle에서 고친 뒤 `Update`한다. 추출 객체의 형상과 Properties는 직접 편집하지 않는다. 추출 위치만 어긋났다면 `Move`로 배치 원점을 맞춘다.
   - **직접 작도한 도면.** 2D로 설계를 발전시키는 작업은 2D 원본에서 한다. 시트별 선·치수·주석은 해당 Layout의 PageSpace에, 여러 도면이 공유하는 그리드 같은 원본은 ModelSpace에 둔다. 선종·선폭·색은 프로젝트 Drawing Recipe의 레이어에서 ByLayer로 적용한다. 문의 여닫이 궤적을 파선으로 그릴 때는 호 하나에 해당 선종을 적용한다. 필요한 선 레이어를 추가하면 같은 정의를 레시피에도 반영한다. 대상의 이름과 분류는 객체 Name과 [메타데이터](../policy/metadata.md)에 기록한다.
   - **Layout과 Detail View 구성.** 도면 원본이 올바른데 시트에서 잘리거나 엉뚱한 곳이 보이면 Detail의 대상·시야·축척을 맞춘다. 모델의 절개 뷰를 보여줄 때는 해당 Named View를 Detail에 적용한다. 배치에만 쓰는 Detail 테두리와 출력 경계는 프로젝트의 비출력 레이어에 둔다.
3. **실제 출력에서 검토.** `capture_04-defined_view` tool로 Layout을 캡처하고, 실제 전달 형식에서 축척·표기·잘림·읽힘을 확인한다. 도면에 필요한 기준선이 보이는지, 추출한 단면이 의도한 층과 부재를 지나는지 본다. 설계 검토에서는 캡처에서 공간과 사용 관계를 읽고 형상과 치수로 대조한다. 검토할 관계에 맞춰 평면·단면·입면과 3D View(Perspective, Parallel) 중 필요한 뷰를 고른다. 도면에서 확인할 때는 필요한 평·단면·입면을 추출하거나 갱신하고, 모델 안쪽을 봐야 할 때는 3D View에 Clipping Plane을 활용한다. 지정된 Named View도 검토에 활용한다. 확인한 사실, 해석, 가정, 미확인을 구분한다.

   도면에서 공간의 구성과 사용 관계를 읽을 때 [도면 분석 지침 원문](../docs/drawing-analysis.md)을 참고한다.
