# 도면 제작·검토(Layout·Detail)

Layout은 도면을 구성하는 시트이고, Detail View는 그 안에서 모델이나 도면의 특정 범위를 보여주는 창이다. Layout과 Named View는 설계의 일부다. 제목과 메타데이터에 내용과 역할을 압축하고, Layout의 description에는 검토 논점과 이슈를 요약한다. 단, 텍스트의 사용은 최소화하고, 도면이 Develop내용을 스스로 말하게끔 도면을 작성하여야 한다. 단, 도면만으로 알 수 없는 결정이나 미결 사항은 텍스트로 남긴다. outdated 레이아웃/도면은 반드시 제거해야 한다.

1. **열기 또는 구성.** 무엇을 보여주고 판단할지에 맞춰 범위와 축척을 정한다. 기존 Layout·Detail중에서 현재 필요한 도면과 조건이 유사한 것은 기존의 것을 활용한다. Detail이 없거나 도면 갱신이 필요하면 필요한 것만 새롭게 구성한다.
2. **원본 편집 또는 추출.** 직접 설계하는 2D 원본은 해당 원본을 편집하며 이를 위해 3D 모델 생성을 강제하지 않는다.  `PlanSection` 툴로 모델에서 평·단면을 추출·갱신(update)한다. PlanSection 산출물은 편집 금지이다. 별도로 작성하는 2D객체는 해당 Layout의 `PageSpace`에서 작성해야 한다. 단 여러 도면에 공통으로 보여야 하는 2D객체는 `ModelSpace`에 둔다.

   작도할때는 어떤 도면에 있더라도 동일한 레이어(선유형+그에 맞는 property)체계를 적용한다. 해당 프로젝트에서 정한 Drawing Recipe 툴을 사용해 작도 체계가 적용된 레시피를 갱신하여 그 레이어 체계를기반으로 레이어를 사용해 작도한다. 기타 객체에 대한 정보의 기입은 객체 Name 및 metadata 규약에 있는 key들을 활용해서 정보를 작성한다.
   작도한 객체의 properties(`Linetype`, `PrintWidth`, `PrintColor`, `DisplayColor` 등..)는 ByLayer로 지정한다. 필요한 선 레이어가 없으면 도면에 추가하는 동시에 사용한 레시피에도 추가한다.
3. **실제 출력에서 검토.** `capture_04-defined_view` tool로 Layout을 캡처하고, 실제 전달 형식에서 축척·표기·잘림·읽힘을 확인한다. 설계 검토에서는 캡처에서 공간과 사용 관계를 읽고 형상과 치수로 대조한다. 검토할 관계에 맞춰 평면·단면·입면과 3D View(Perspective, Parallel) 중 필요한 뷰를 고른다. 도면에서 확인할 때는 필요한 평·단면·입면을 추출하거나 갱신하고, 모델 안쪽을 봐야 할 때는 3D View에 Clipping Plane을 활용한다. 지정된 Named View도 검토에 활용한다. 확인한 사실, 해석, 가정, 미확인을 구분한다.

   도면에서 공간의 구성과 사용 관계를 읽을 때 [도면 분석 지침 원문](../docs/drawing-analysis.md)을 참고한다.
